# Changelog

## [2.8.0] - 2026-04-28
### Added
- **Configurable Transaction Categories**: Introduced a manageable system for transaction classification with a strict 10-category limit.
- **Category Management UI**: New management interface in Settings for admins to add, delete, and view transaction categories.
- **Automated Fuel Categorization**: The system now automatically assigns the "Fuel Station" category to all transactions generated by the IoT fuel pump gateway.
- **Categorized Reporting**: Enhanced the Transaction Report with a new category filter and included transaction categories in the itemized data breakdown.
- **POS Category Selection**: Integrated category selection into the checkout workflow, allowing cashiers to classify sales (defaulting to "General").
- **CRM Activity Enhancement**: Updated the Customer Activity Timeline to display transaction categories for better historical context.

### Changed
- **Database Schema**: Added `transaction_categories` lookup table and migrated the `transactions` table to include a `category` column.
- **Transaction Orchestration**: Updated `transactionService` to enforce business logic for automated categorization and payload integrity.

## [2.7.0] - 2026-04-28
### Added
- **Dedicated Pump Controller Page**: Created a new configuration module at `/pump-controller` to manage fuel pricing, tank capacities, and refuel speeds independently of the general Settings page.
- **Sidebar Navigation Update**: Added "Pump Config" link with a dedicated Fuel icon, conditionally rendered based on the master sandbox flag.

### Changed
- **Settings Page Refactor**: Decoupled IoT pump simulation settings from the core system settings. Removed all fuel-related state and UI components from the Settings page to improve modularity.

## [2.6.0] - 2026-04-22
### Added
- **Global Command Search**: Hybrid search with instant local page filtering + debounced (300ms) DB query. Results are grouped into Pages, Database (Customers/Products/Transactions) with type-aware icons. Clears on outside click.
- **Profile Glance Dropdown**: Navbar avatar now opens a dropdown showing signed-in username, role badge, quick links to Settings & Audit Logs, and a **"Terminate Session"** logout button.
- **Notification Bell Hover Panel**: Placeholder panel noting "No alerts from IoT Gateway" — ready for future Socket.io pump/MDM alert integration.
- **Transaction Search**: `unifiedSearchService` now also queries the `transactions` table by UUID/invoice number prefix and merges results into the unified search response.

### Changed
- **Navbar**: Full rewrite — search bar wired to `useSearchStore` (Zustand), profile dropdown replaces static avatar, notification bell gets hover panel.
- **`useSearchStore`**: Extended `SearchResult` type to include `transaction` and `page` variants.

## [2.5.0] - 2026-04-22
### Added
- **User Activity Timeline** (`/admin/users/:id/activity`): New admin-only page (mirroring CRM `/crm/:id`) showing a user's full audit timeline — login events, API mutations, password resets, and account toggles — with action-based filters.
- **User Enable/Disable Toggle**: Administrators can now disable any user account. Disabled users are blocked **immediately** at the auth middleware layer — existing JWT sessions are invalidated on the next request without requiring re-login.
- **Admin Password Reset**: Admins can reset any user's password from the Settings page via a secure modal (no password is ever shown in the UI).
- **Global Mutation Audit Middleware**: All authenticated `POST/PUT/PATCH/DELETE` API calls are now automatically logged to `audit_logs` with user ID, IP address, and endpoint path.
- **Login Audit Events**: Successful logins now create a `LOGIN` record in `audit_logs`, establishing the full login/logout history chain per user.

### Changed
- **`authMiddleware.ts`**: Now performs a real-time database check on every request to verify the user's `is_active` status. This ensures account disabling takes effect immediately across all active sessions.
- **`authController.ts`**: Login response now includes `username` in the payload, resolving the stale "User" display issue in the Navbar.

### Fixed
- **Admin Account Deletion Guard**: Admin-role users can no longer be deleted via the API or Settings UI. A 🔒 lock icon replaces the delete button; the backend also enforces a `403 Forbidden` response.

## [2.4.1] - 2026-04-22
### Added
- **System Maintenance (Purge)**: Implemented an admin-only "Purge All Data" feature in Settings to safely clear transactional and customer data using optimized database transactions.
- **Inventory Restock Flow**: Enhanced duplicate SKU/Name detection with a "Restock Instead?" shortcut, allowing users to instantly switch from product creation to restocking when an existing item is found.
- **Authentication Sync Refactor**: Synchronized the `Navbar`, `Login`, and `Role Utility` to display real-time user session data, featuring dynamic role-based avatars and professionally mapped role labels.

### Fixed
- **Customer Duplicate Handling**: Improved error feedback when creating duplicate customer records, now returning a clear `409 Conflict` status and user-friendly message.
- **Schema Validation Consistency**: Resolved a `400 Bad Request` issue in the POS checkout flow by updating Zod schemas to handle `null` customer IDs and the new `points_redeemed` field.
- **Security & DB Stability**: Fixed a critical security regression in `systemRoutes.ts` by re-enabling admin RBAC and restoring the standard database connection pattern.

## [2.4.0] - 2026-04-21
### Added
- **Smart Input Layer**: Integrated FTS5 fuzzy search for customers and inventory across the POS system using Levenshtein distance matching to prevent data fragmentation.
- **Hybrid Data Model**: Upgraded the inventory management system to support category-specific attribute entry (e.g., Oil Viscosity, Spark Plug Thread Size) mapped to a JSON metadata schema, complete with automatic canonical naming.
- **Security Audit Vault**: Exposed AES-256 encrypted `audit_logs` to the frontend via a dedicated admin dashboard (`/admin/audit`), allowing administrators to safely decrypt and view sensitive mutation payloads.
- **Master Metadata Editor**: Added an admin interface (`/admin/metadata`) for defining custom JSON schema keys for Customer and Product profiles, enabling scalable metadata governance.
- **Identity Merging (CRM)**: Introduced a dual-pane UI (`/crm/merge`) and backend mechanism (`POST /api/customers/merge`) to consolidate duplicate customer records, re-pointing all associated transactions, audits, and loyalty points.
- **POS Loyalty Redemption**: Implemented a real-time loyalty point verification and redemption toggle directly within the POS checkout modal.
- **Fuel Command Center**: Built `/reports/fuel` to monitor real-time tank telemetry, daily burn rates, and predictive depletion dates based on POS transactional outflow.
- **Margin Analytics Dashboard**: Deployed `/reports/margin` to visualize Revenue vs. COGS, offering real-time gross profit projections and daily performance charts.
- **Admin Protected Routes**: Upgraded the `ProtectedRoute` component to accept a `requireAdmin` prop, enforcing role-based access control (RBAC) via local storage validation.

### Fixed
- **TypeScript & Linting Errors**: Resolved IDE-reported TypeScript issues including missing `metadata` definitions in the `Product` interface, duplicate state variables in the POS checkout, and malformed inline CSS template literals.
- **API Routing**: Fixed a missing import for `fuelConfigRoutes` in the Express server index, restoring access to pump configuration endpoints.

## [2.2.1] - 2026-04-15
### Fixed
- **Pending payments now stored in dedicated container**: Pending pump payments are fetched from the POS database (`GET /transactions/pump-pending`) and displayed independently of pump state. Resetting a pump no longer removes pending payments from the queue.
- **Pump reset no longer breaks checkout**: Checkout modal receives `pendingTxId` directly from the DB query — no fragile session_id matching. Payment can be completed even after the pump has been reset to IDLE.

### Added
- **Authorize mode selector**: Three pump authorization modes:
  - **Free Pump**: Unlimited dispensing (manual stop)
  - **By Litre**: Set target litres (e.g., 10L) — pump auto-stops when reached
  - **By Rp**: Set target currency amount (e.g., Rp 50,000) — auto-calculates litres and auto-stops
- Auto-calculation preview: shows estimated cost/litres before authorization
- Progress bar during preset pumping with percentage indicator
- PRESET badge on pump card header when using a target

### Changed
- `PumpStateMachine.authorize()` now accepts optional `targetLitres` and `targetCost` parameters
- `PumpStateMachine.updateTelemetry()` returns `boolean` — `true` signals target reached for auto-stop
- `TelemetryEmitter` handles auto-stop when preset target is reached
- `PumpCheckoutModal` no longer searches for pending transactions — receives `pendingTxId` as prop
- Checkout button removed from PumpHMI card — checkout only via Pending Payments queue

## [2.2.0] - 2026-04-15
### Added
- **Multi-Pump Stations**: Run N simultaneous pumping stations (default: 2, configurable via `NUM_PUMPS` env).
  - Each pump has independent state machine (IDLE/AUTHORIZED/PUMPING/COMPLETED/FAULT/LOCKED).
  - REST endpoints parameterized by `:pumpId` (e.g., `/api/pump/1/authorize`).
  - Aggregated telemetry: Socket.io broadcasts `pumps[]` array with per-pump status.
  - Per-pump chaos engine: inject faults independently per station.
  - Pump HMI cards rendered side-by-side in a responsive grid.

- **Semi-Automatic Transaction Workflow**: Complete audit trail for gasoline sales.
  - Completed pump sessions create `PENDING` transactions in POS database.
  - "Pending Checkout" queue shows all pumps awaiting payment.
  - **PumpCheckoutModal**: Cashier checkout with bill summary, customer selection (guest/existing/new), payment method (cash/transfer/QRIS/debit/CC), and cash change calculation.
  - `POST /api/transactions/pump-finalize`: Finalizes pending tx with payment method, customer, and user.
  - `GET /api/transactions/pump-pending`: Lists all pending pump transactions.
  - Transactions include `pump_id` for per-station tracking in reports.

### Changed
- **Database Schema**: Added `pump_id`, `payment_status`, `reference_id`, `cash_handed`, `cash_change`, `adjustment_amount` columns to `transactions` table. Migration runs automatically via seed.
- **Deprecated Components**: Old single-pump HMI components (NozzleAnimation, FlowAnimation, DigitalCounter, PumpControls, ChaosPanel, StatusIndicator) stubbed out — all functionality now lives in the new `PumpHMI` card component.


## [2.1.0] - 2026-04-15
### Added
- **Fuel Storage Tank Simulation**: Underground tank capacity tracking integrated with pump controller.
  - `StorageTankManager` class — per-fuel-type tank with capacity, level, and refueling simulation.
  - Configurable `tank_capacity` (L) and `refuel_speed` (L/s) per fuel type from Settings page.
  - Database migration: added `tank_capacity` and `refuel_speed` columns to `fuel_config`.
  - Pump controller fetches fuel configs from POS API on startup to auto-initialize tanks.
  - Tank deduction during pumping — auto-stops when tank empties.
  - Refueling simulation: tanker delivery fills at configurable speed, auto-completes at capacity.
  - Pump LOCKED state: pump blocked during refueling, auto-unlocks when delivery finishes.
  - New REST endpoints: `GET /api/tank/status`, `POST /api/tank/refuel`, `/refuel/cancel`, `/set-level`, `/reload-config`.
  - `TANK_EMPTY` chaos mode fault — drains active tank to 0.
  - SVG `TankGauge` component — animated vertical bar gauges per fuel type (green/amber/red), refuel pulse, LOW/FILL badges.
  - `TankControlPanel` — refuel/cancel controls, progress bars, manual level slider for testing, PUMP LOCKED indicator.
  - Settings page expanded: inline editing for tank capacity and refuel speed per fuel type.

  - REST API: `/api/pump/authorize`, `/start`, `/stop`, `/reset`, `/status`, `/chaos`.

  - WebSocket connection status indicator with state badges.

  - `POST /api/transactions/pump-inject` endpoint with dedicated middleware.
  - Service JWT validation (PUMP_SERVICE_SECRET).
  - Localhost-only origin enforcement for pump injection.
  - Idempotency check via `reference_id` to prevent double-entry.
  - Numeric sanitization (negative values, overflow protection).
  - Pump transactions visible in main Transactions page with `Fuel_Sim` badge.
- **Multi-Service Ecosystem**:
  - Root `package.json` with `concurrently` — single `npm run dev` starts all 3 services.
